오늘의 지도 다섯 개의 독립 사례

한 업무의 다섯 장면을 AI로 해결한다배경은 하나 — 「직원 역량개발 연수」 운영 업무입니다. 다섯 장면을 각각 독립된 사례로 실습합니다.

당신은 연수 운영 담당자입니다. 신청자 명단을 정리하고, 만족도 설문을 분석하고, 정산 서류를 발급하고, 다음 접수를 자동화하고, 보고 장표를 만듭니다. 오늘 이 다섯 가지를 전부 — 단, 손으로는 하나도 하지 않고 — 끝냅니다.

CASE 1 엑셀 함수 × AI

신청자 명단 150명, 수식으로 끝낸다부서도 프로그램도 코드번호뿐인 명단. 지원금 산정과 우선선발 판정까지 — 함수를 외우지 않고 해결합니다.

상황. 연수 신청 마감 직후, 150명의 신청 명단이 도착했습니다. 그런데 부서와 프로그램이 코드로만 적혀 있습니다. 오늘 안에 ① 코드를 이름으로 바꾸고 ② 1인당 예상 지원금을 산정하고 ③ 우선선발 대상을 판정하고 ④ 프로그램별 신청 현황까지 집계해야 합니다. 손으로 하면 한나절 — 수식이면 몇 분입니다.

실습 1 — 연수 신청자 명단

신청자 150명 + 부서코드표 + 프로그램표 + 집계 시트. 목표 열이 비어 있습니다.

파일 받기

1-1 · 준비 — 데이터는 빼고, 구조만 넘긴다

AI에게 수식을 시키려면 시트 구조를 알려줘야 합니다. 열 이름을 일일이 타이핑하는 대신 — 데이터를 지우고 구조만 남긴 사본을 만들어 파일째 첨부합니다. 실무에서 그대로 쓰는 요령입니다.

  • 실습 파일을 열어 '신청자명단' 시트에서 3행부터 아래 데이터를 모두 삭제합니다 — 헤더(1행)와 예시 1행(2행)만 남깁니다.
  • 부서코드표·프로그램표 시트는 코드 기준표이므로 그대로 둡니다.
  • 파일 → 다른 이름으로 저장 → 「신청자명단_구조.xlsx」
  • ChatGPT에 이 구조 파일을 첨부합니다 — 이제 열 구조를 한 글자도 설명할 필요가 없습니다.
이 요령이 곧 보안 수칙입니다.

실무 파일에는 이름·연락처 같은 개인정보가 들어 있어 통째로 올릴 수 없습니다. 구조 사본을 넘기고 → 수식만 받아 → 원본에서 실행하면, 데이터는 내 PC를 떠나지 않습니다. 예시 행이 필요하면 가짜 값 한 줄을 만들어 두면 됩니다.

1-2 · 첫 요청 — 원하는 결과만 말한다

함수 이름은 말하지 않습니다. "무엇을 채우고 싶은지"만 말하면 — 함수는 AI가 고릅니다.

PROMPT 1 · 첫 요청 (구조 파일 첨부 후)
첨부한 파일은 연수 신청자 명단의 구조만 남긴 사본이야. 실제 파일에는 신청자명단 시트 2행부터 151행까지 150명이 들어 있어. 신청자명단 시트의 부서명·프로그램명·교육시간 열이 비어 있는데, 각각 부서코드표 시트와 프로그램표 시트에서 코드에 맞는 값을 찾아와 채우고 싶어. 세 열에 넣을 수식을 만들어줘. 그대로 붙여넣을 수 있게 해주고, 각 수식이 어떤 원리로 동작하는지 한 줄씩 설명도 붙여줘.
받은 수식은 2행에 붙여넣고, 채우기 핸들로 아래까지. 셀 오른쪽 아래 모서리를 더블클릭하면 150행까지 한 번에 채워집니다. 결과가 코드가 아니라 이름으로 바뀌는 순간을 확인하세요.

1-3 · 복합 산정 — 여러 정보를 조합해 결과치를 추산한다

이제 진짜 실무형 수식입니다. 지원금은 교육시간 × 시간당 단가 × 사전과제 제출 여부에 따른 지급률 — 두 시트의 정보와 조건 판단이 한 수식에 들어갑니다. 요령은 하나입니다: "수식 줘"가 아니라, 지급 규칙을 조목조목 명시합니다.

PROMPT 2 · 복합 산정 (규칙 명시)
이번엔 예상 지원금 열을 채우자. 지급 규칙은 이래. - 지원금 = 신청한 프로그램의 교육시간 × 그 프로그램의 시간당 지원단가 - 단, 사전과제 제출이 "Y"면 전액, "N"이면 절반만 지급 - 결과는 원 단위, 천 단위 구분기호가 보이게 이 규칙대로 계산되는 수식을 만들어줘. 수식만 주지 말고 계산 구조를 단계별로 설명하고, 내가 규칙을 애매하게 말한 부분이 있으면 지적해줘.
이 수식이 하는 일을 사람이 하면 — 신청자 1명마다 프로그램표를 찾아 단가를 확인하고, 사전과제 여부를 보고, 계산기를 두드립니다 × 150번. 수식은 이 판단 전체를 규칙 한 줄로 만든 것입니다. "여러 표의 정보를 조건에 따라 조합해 값을 추산한다" — 사무 업무 수식의 본질입니다.

1-4 · 검증과 디버깅 — AI도 틀린다

결과를 그대로 믿지 않습니다. 아무 신청자 한 명을 골라 손으로 대조해 보고 — 이상하면 그 자리에서 따집니다. 오늘 사례에서 가장 중요한 지점입니다.

PROMPT 3 · 디버깅 (결과가 이상할 때)
5행 신청자의 지원금이 이상해. 이 사람은 사전과제가 "N"인데 전액으로 계산된 것 같아. 말이 되는지 검증하고, 문제가 있으면 원인 분석해서 제대로 된 수식 다시 줘.
AI는 첫 답에서 곧잘 틀립니다. 절대 참조($)를 빠뜨리거나 범위를 잘못 잡는 일이 흔합니다. "결과가 이상하다 → 원인 분석해서 다시 줘" 한 마디면 AI가 스스로 찾아 고칩니다. 수식이 아예 안 먹고 #NAME?가 뜨면 — "우리 엑셀에서 이 함수가 안 되는 것 같아. 같은 결과를 내는 다른 방법으로 다시 줘"라고 하세요. 버전 문제도 함수 이름을 몰라도 해결됩니다.

1-5 · 조건 판정 — 우선선발 가리기

PROMPT 4 · 판정 규칙 명시
우선선발 열을 채우자. 판정 규칙은 이래. - 사전과제를 제출했고, 그리고 작년 이수시간이 20시간 미만인 사람만 "우선" - 나머지는 전부 "일반" (작년에 교육 기회를 적게 받은 사람에게 먼저 주는 규칙이야) 수식을 만들어줘. 두 조건이 모두 맞아야 한다는 게 핵심이야.

1-6 · 조건 집계 — 데이터가 말을 하기 시작한다

PROMPT 5 · 집계 표 완성
마지막으로 '집계' 시트의 프로그램별 현황 표를 채우자. 비어 있는 세 칸 — 신청 인원 · 정원 · 정원 대비 신청률(%) — 에 넣을 수식을 만들어줘. 완성되면, 어떤 프로그램이 정원을 초과했는지도 알려줘.
집계가 끝나면 보이는 것.

「AI 활용 실무」 신청 49명 vs 정원 30명 — 정원 160% 초과입니다. 1-5에서 만든 '우선선발' 판정이 왜 필요했는지, 데이터가 스스로 답합니다. 좋은 집계는 다음 의사결정(분반? 추가 개설?)의 근거가 됩니다.

학습 포인트 — 함수 이름은 끝까지 등장하지 않았습니다. 우리는 "무엇을" + "어떤 조건으로"만 말했습니다. 그리고 가장 중요한 것은 1-4의 감각 — 수식은 한 건을 손으로 대조한 뒤에 씁니다.

2-1 · 분석부터 시키지 않는다 — 계획을 먼저 합의

PROMPT 6 · 데이터 파악 + 분석 계획 (파일 첨부 후)
[역할] 너는 교육 운영 데이터를 다루는 분석가다. [맥락] 첨부한 파일은 사내 연수 6개 과정의 만족도 설문 응답(72명)이다. 내일 부서장에게 결과와 개선 방향을 보고해야 한다. [요청] 아직 분석하지 마. 1. 데이터 구조(열 구성·응답 수·척도)를 먼저 파악해서 요약해줘. 2. 보고 목적에 맞는 분석 계획을 4단계 이내로 제안해줘. 3. 내가 "진행"이라고 하면 그때 순서대로 분석해줘.
왜 계획부터? 파일을 던지고 "분석해줘"만 하면 AI가 임의 방향으로 달립니다. 계획을 먼저 받고 다듬는 10초의 합의가 결과물의 방향을 결정합니다 — 사람에게 일을 맡길 때와 같습니다.

2-2 · 정량 분석 + 차트

PROMPT 7 · 문항별 · 과정별 분석
진행. 먼저 정량 분석부터. 1. 문항별(Q1~Q5) 전체 평균을 표로 — 가장 높은 문항과 가장 낮은 문항이 뭔지 짚어줘. 2. 과정별 전반 만족도(Q1) 평균을 막대 그래프로 그려줘. (그래프 안 라벨이 깨지면 다시 그려줘) 3. 표와 그래프에서 읽히는 특징을 3줄로 요약해줘. 수치 근거를 함께.

2-3 · 주관식 — 자유 의견을 유형으로

PROMPT 8 · 자유 의견 분류
이번엔 '개선 의견(자유 기재)' 열을 분석해줘. 1. 의견을 유형별로 분류하고, 유형마다 건수와 대표 의견 1개씩 표로 정리해줘. 2. 정량 결과(문항 점수)와 일치하는 신호가 있는지 연결해서 해석해줘. (예: 점수가 낮은 문항과 관련된 불만이 실제로 많은가?) [제약] 의견 원문에 없는 내용을 만들어내지 말 것.

CASE 3 VBA 매크로 × AI — 거래명세서 자동 발급

PROMPT 11 · 마스터 프롬프트 정돈 요청
아래는 내가 만들고 싶은 VBA 자동화 작업의 러프한 요청이야. 이걸 그대로 던지면 동작 안 하는 코드가 나올 가능성이 높아. 부족하거나 빠진 맥락(값을 채울 위치, 파일명 규칙, 예외 처리 등)을 업계 통상에 맞춰 보강해서 마스터 프롬프트 형태로 정돈해줘. 첨부한 파일의 실제 구조를 근거로 삼고, 내가 추가로 확인해야 하는 부분은 [채워주세요] 빈칸으로 표시해줘. --- 러프한 요청 --- 이 엑셀파일 양식 파악해서 거래명세서 자동발급 VBA 코드 만들어줘. 1번 시트는 거래명세서 양식, 2번 시트는 데이터. 2번 시트 데이터로 1번 양식 채우고 각 행별 PDF로 저장. 파일 경로 설정 가능해야 함.
돌아오는 것. 작업 개요 · 값 채울 위치 · 파일 저장 규칙(예: "거래명세서_[거래처명]_[날짜].pdf") · 예외 처리(빈 행 중단, 파일명 중복)까지 정돈된 마스터 프롬프트가 돌아옵니다. [채워주세요] 빈칸만 내 상황에 맞게 채우면 됩니다.

CASE 4 구글 폼 + 앱스 스크립트

내가 없어도 돌아가는 시스템을 만든다다음 연수 접수 준비 — 신청이 들어오면 접수 확인 메일이 자동으로 나갑니다. 퇴근 후에도, 주말에도.

상황. 다음 연수 접수가 시작됩니다. 지금까지는 신청을 확인하고 한 명 한 명 접수 안내 메일을 보냈습니다. 오늘 만드는 것은 파일이 아니라 시스템입니다 — 구글 폼으로 신청을 받고, 제출되는 순간 확인 메일이 자동 발송되게 합니다. CASE 3과의 차이: VBA는 내가 실행 버튼을 눌러야 하지만, 이번 것은 스스로 실행됩니다.

개념은 이 한 줄이면 충분합니다 — Apps Script는 VBA의 구글판입니다. 폼·시트·Gmail·드라이브를 코드로 움직이며, 결정적 차이는 트리거: 조건이 갖춰지면 스스로 실행됩니다.

  • 응답 탭 → Sheets에 연결 — 응답이 쌓일 스프레드시트가 만들어집니다

  • 메일이 안 오면: 편집기 왼쪽 실행 기록 메뉴 → 실패한 실행을 클릭 → 오류 메시지를 복사해 AI에게 "이 오류 고쳐줘"
  • 수정한 코드로 저장 → 다시 폼 제출 → 될 때까지 이 반복이 곧 실무입니다
헷갈리기 쉬운 두 가지. ① 편집기의 배포(Deploy) 버튼은 누르지 않습니다 — 배포는 웹앱 공개용 기능이고, 폼 자동화는 트리거만 있으면 됩니다. ② "실행 완료"는 자동화 완성이 아닙니다 — 수동 실행에 성공했다는 뜻일 뿐, ⏰ 트리거 목록에 '양식 제출 시' 한 줄이 있어야 스스로 돕니다.
